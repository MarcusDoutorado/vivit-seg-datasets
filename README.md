# vivit-seg-datasets

Groundtruth annotations, dataset-curation metadata, and per-movie verification material for **MSC** (MovieScenes Curated), the verified movie-scene-segmentation benchmark used in our multimodal scene segmentation work. Model code lives in the companion repository, [vivit-seg](https://github.com/Wan-Song/vivit-seg) — this repository contains only the data-side artifacts, which don't belong in the model codebase.

We do **not** redistribute the source videos themselves (copyright). What's here is annotation (shot/scene boundaries as frame indices, movie identifiers, verification notes) plus a small number of low-resolution sample frames used strictly to help someone who has independently sourced a movie confirm they have a release that matches our shot/scene boundaries.

## Contents

- **`shots.csv` / `scenes.csv`** — shot and scene boundaries (frame indices) for **all 64 movies** of the MovieScenes 64-movie test split, as originally sourced, before verification.
- **`shots_trust.csv` / `scenes_trust.csv`** — the same, restricted to the **54 movies** whose official groundtruth we verified as correct (i.e. `shots.csv` minus the 10 movies listed in `excluded_videos.csv`). This is the set actually used in our experiments and reported in the paper. **This is the only difference between the two pairs of files** — same boundaries, `_trust` is just pre-filtered to the verified subset.
- **`msc.csv`** — simple id → title lookup.
- **`msc_movies.csv`** — id → title, year, genres, runtime, IMDb identifier, and the exact filename of the video file we sourced for each movie (useful when a title has more than one candidate release, as documented in `msc_gt_adjust.csv`). **Sourced directly from IMDb** (title, year, genres, runtime as provided by imdb.com for each identifier) — not something we computed or edited.
- **`excluded_videos.csv`** — the 10 movies excluded from the 64-movie split, with the specific groundtruth issue identified for each (mirrors the table in the paper).
- **`msc_gt_adjust.csv`** — per-movie verification log: frame offsets applied at scene start/end during reconciliation (`frames_start`/`frames_end`), whether each movie's scene/shot groundtruth checked out (`gt_scenes_ok`/`gt_shots_ok`), and whether the movie made it into the verified 54 (`use_video`).
- **`table_msc_dataset_info.csv`** — the formatted summary table (one row per movie, alphabetical, with a Total row) that appears in the paper: scenes, shots, frames, duration, and the specific BBFC-classified release (Cinema/Home Entertainment, year) each movie's frame count corresponds to. Frames and Duration come from cross-referencing the frame count of our own downloaded copy of each video (measured directly via `ffprobe`) against BBFC runtimes for every classified release of that title, converted to frames at 24fps — not from IMDb's rounded runtime. For 50 of 54 movies this match is within 30 seconds; the remaining 4 (marked `*`) differ by more, likely because our copy is a specific cut or regional release not separately catalogued by the BBFC — the closest available release is still reported, as the best available reference. See `docs/methodology.md` for the full methodology.
- **`msc_frames_bbfc.csv`** — the underlying research behind the Duration/Version columns above: for every movie, every BBFC-documented release we found (Cinema, Home Entertainment, other versions) with runtime to the second, our own `ffprobe`-measured frame count, and the reasoning for which release was selected as the closest match (plain-language, one row per movie). Use this if you want to see the calculation behind `table_msc_dataset_info.csv`, or to double-check/dispute a specific movie's matched release.
- **`msc_ffprobe_verification.csv`** — raw `ffprobe` measurements (frame rate, frame count, duration) of our own reference copy of all 64 movies (54 kept + 10 excluded), independent of any groundtruth annotation. This is the source of the per-movie `fps` figure in `msc_manifest.csv` below.
- **`msc_manifest.csv` / `msc_manifest.json`** — the single structured-metadata file for the 54-movie MSC-trust set: one row per movie with `msc_id, imdb_id, movie_title, bbfc_release_version, bbfc_runtime, fps, frame_count, shot_count, scene_count`. Generated by `scripts/generate_msc_manifest.py` (joins `msc_movies.csv` × `table_msc_dataset_info.csv` × `msc_ffprobe_verification.csv`) — re-run that script if any of its inputs change, rather than hand-editing the manifest.
- **`msc_checksums.csv`** — reference SHA-256 checksum of our copy of each of the 54 movies (same content as `docs/download_guide.md`, in machine-readable form). Generated alongside the download guide by `scripts/generate_download_guide.py`; consumed by `scripts/verify_msc_download.py`.
- **`verification_frames/`** — 3 low-resolution sample frames per movie, one subfolder per movie (`msc_<id>/`), so a downloaded copy can be spot-checked against ours. See `docs/methodology.md` for the reasoning and naming convention.

## Reproducing the dataset from your own copies

See [docs/how_to_run.md](docs/how_to_run.md) for a quick, practical guide to every script. Summary:

1. **Check what to source**: `MSC/msc_manifest.csv` lists the 54 movies with the specific BBFC-classified release our copy corresponds to; `docs/download_guide.md` adds the exact filename we used and its reference SHA-256 checksum for each, plus a note on what a checksum match/mismatch does and doesn't imply. Regenerate the guide (and `MSC/msc_checksums.csv`) against your own files with `python3 scripts/generate_download_guide.py --videos-dir /path/to/your/videos`.
2. **Verify automatically**: `python3 scripts/verify_msc_download.py --videos-dir /path/to/your/videos` checks each movie against `MSC/msc_checksums.csv` (byte-identical fast path) and falls back to an `ffprobe` frame-count/fps/duration comparison against `MSC/msc_ffprobe_verification.csv` for anything that doesn't match exactly (e.g. a different re-encode of the same release), printing a PASS/FAIL report (`--report-out` to also save it as CSV). Then spot-check a few frames from `MSC/verification_frames/` against your copy before trusting `shots_trust.csv`/`scenes_trust.csv` on it.
3. **Extract features**: `scripts/01_generate_shots.py` through `scripts/08_filter_missing_visual.py` take you from your sourced movies all the way to the shot-pair/LOVO training CSVs used in our experiments (shot-cutting, key-frame sampling, MFCC/LogMel audio, Whisper transcription + text embeddings, ViViT visual embeddings, data augmentation, leave-one-video-out splits). These are standalone, CLI-only ports of the pipeline developed and maintained in the companion model repository, [vivit-seg](https://github.com/Wan-Song/vivit-seg) (`continuity` branch, `experiment_manager/` and `src/preprocess/`/`src/datasets/`) — see `scripts/README.md` for the full run order, required system dependencies (`ffmpeg`/`ffprobe`), example invocations, and exactly what was adapted or dropped versus the original. Every script was smoke-tested end-to-end on a real movie (`msc_0005`) against the original pipeline's reference output (see `scripts/README.md`'s Validation section) — this covered CPU-only audio/text extraction and a small ViViT visual-embedding run, but not a full 54-movie pass (impractical to verify in full here; expect it to take substantial time and disk space) nor GPU-scale visual extraction throughput.

## Verified subset vs. full split

MSC is derived from MovieScenes' 64-movie test split. We manually verified every movie's official groundtruth against the actual video content; 10 could not be reconciled (see `excluded_videos.csv` for the specific issue per movie) and were excluded. The remaining 54 movies (`shots_trust.csv` / `scenes_trust.csv`) are what we report results on throughout the paper and thesis. Full methodology in `docs/methodology.md`.
